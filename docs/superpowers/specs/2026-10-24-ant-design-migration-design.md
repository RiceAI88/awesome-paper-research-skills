# Ant Design 整体迁移设计

日期：2026-10-24

## 目标与范围

将「论文科研 Skills 排行榜」从原生 HTML / CSS / JavaScript 整体迁移至 React + Vite + Ant Design。用户已选择整体迁移方案。本设计用于明确实施边界与验收标准，等待用户确认后实施。

保持已确定的首页信息层级：紧凑标题、介绍下方的搜索框、六个科研任务入口、统计信息、筛选区和榜单。主色为 `#691eff`，默认浅色采用白底与浅紫背景；深色模式使用可读性更好的紫色层级。

全站界面字体继续采用用户指定的字体栈：

```css
-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans", sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol", "Noto Color Emoji"
```

本次不增加新的业务功能，不改变榜单收录规则、排名算法及每日运行时间，不重新设计品牌或首页布局，不增加服务器、数据库或登录系统。

## 方案选择

1. 整体迁移（用户已选择）：由 React 统一管理页面状态，使用 Ant Design 替换交互控件。迁移范围较大，但组件、状态和主题保持一致。
2. 局部接入（未选择）：只替换部分控件，保留原生代码。短期改动少，但需要同时维护 React 和直接操作 DOM 的两套交互方式。

## 技术方案

- React + Vite，使用 JavaScript / JSX，避免额外引入类型迁移工作。实施时核实依赖兼容性，并提交 npm 锁文件。
- 采用 Ant Design 稳定版，通过 `ConfigProvider` 统一字体、主色、圆角、中文 / 英文组件文案与明暗主题。
- 使用 React 状态和事件替换旧的字符串拼接与 DOM 事件绑定；不将旧界面嵌在 React 容器中冒充整体迁移。
- 保留轻量 SVG 趋势图，改为 React 组件；不为现有趋势曲线再添加图表框架。
- 将任务匹配、平台识别、筛选排序及 URL 状态处理抽成可测试的纯函数。使用组件局部状态和必要的共享状态，不新增独立状态管理框架。

## 界面与组件对应

| 当前区域 | 迁移方式 |
|---|---|
| 导航、语言与主题切换 | Ant Design Button / Segmented / Tooltip |
| 首屏搜索 | Ant Design Input，保持输入即时筛选 |
| 六个科研任务入口 | Ant Design Button，保留选中状态和「全部 Skills」 |
| 统计信息与目录 | Ant Design Card / Statistic，保留紧凑与响应式布局 |
| 分类、平台、排序 | Ant Design Select |
| 表格 / 卡片切换、仅看收藏 | Ant Design Segmented / Button |
| 桌面榜单 | Ant Design Table，保持现有排序语义，默认不增加分页 |
| 手机端及手动卡片视图 | Ant Design Card / Tag；窄屏默认卡片视图 |
| 仓库详情 | Ant Design Drawer / Descriptions / Statistic / Tag |
| 增长对比 | Ant Design Modal，保留三仓库上限与原有增长百分比算法 |
| 操作提示与空结果 | Ant Design App 的 message / Empty |

业务组件可按首页、筛选、榜单、仓库详情和趋势图拆分，具体文件粒度由实施者决定，不为每个小标签建立组件。

## 必须保留的行为

1. 六个科研任务支持跨分类匹配；与搜索、分类、平台、收藏和排序组合使用。切换任务时清除上一个分类，保留其他筛选，沿用现有行为。
2. 保留综合排名、趋势、Stars、最近更新、30 天增长五种排序。
3. 保留仓库排名、简介、分类、平台、Stars 与增长、最近更新、Skills 数、引用核验及停更标记。
4. 详情抽屉保留 Topics、信号、许可证、Forks、Issues、日期等字段，以及仓库 / 主页链接、安装命令复制、Markdown 复制和推荐链接。
5. 保留收藏及导出 JSON、最多三个仓库的增长对比；空选择不展示悬浮对比条。历史缺失时展示明确的空状态。
6. 继续读取原有 `ars-lang`、`ars-theme`、`ars-view`、`ars-favorites`、`ars-compare` 本地存储键，用户已有收藏和偏好可继续使用。异常存储值按默认状态处理。
7. 保留 URL hash 的 `q`、`cat`、`task`、`agent`、`sort`、`view`、`lang`、`theme`、`fav`、`repo` 参数，已分享的旧链接仍可恢复筛选和详情。
8. 保留 `/` 搜索、`t` 主题、`l` 语言、`v` 视图、`f` 收藏、`Esc` 关闭快捷键；输入控件使用期间不触发普通字母快捷键。抽屉、弹窗关闭与焦点管理交给 Ant Design。
9. 中文与英文继续共用前端实现，保留 `/` 和 `/en/` 两个访问入口。继续使用当前语言默认值、保存偏好和 URL 指定值的优先关系。

## 数据、构建与部署

- `data/rankings.json`、`data/rankings.js`、`data/history.js` 和 Python 更新脚本继续作为现有数据来源，不在打包时把榜单数据写死到组件代码中。
- 保留数据 JSON / CSV 下载、RSS、sitemap、robots、月报、分享封面、原作者致谢及 MIT 许可证。
- Vite 构建同时输出首页和英文入口，并保留各自 HTML 中的 SEO、canonical、Open Graph 等元信息。JSON-LD 条目仍随榜单生成。
- 配置 GitHub Pages 的 `/awesome-paper-research-skills/` 基础路径，验证英文页、资源路径和仓库详情链接不会跳转到站点根目录或原作者网站。
- 构建时将现有公开数据、月报、封面、下载文件和必要样式复制到 `dist/`。月报继续使用现有静态文档，不重新编写历史内容；不将 Python 脚本、测试或本地工作文件作为网站产物上传。
- Pages 工作流增加 Node 安装、`npm ci`、`npm run build`，只部署 `dist/`。数据更新工作流继续在自动提交后触发 Pages 构建，保证每天的数据仍能上线。
- CI 保留 Python 测试，新增前端逻辑测试和构建检查。开发说明单独放入前端开发文档，避免被每日生成 README 的逻辑覆盖。

## 实施步骤与验收

| 步骤 | 工作 | 验收标准 |
|---|---|---|
| 1 | 建立 Vite 多入口与数据 / 静态文件复制流程 | `npm ci`、构建通过；首页、英文页、月报及数据文件完整输出至 `dist/` |
| 2 | 迁移筛选、任务、状态、语言和主题 | 纯函数测试覆盖组合筛选、排序、任务匹配、旧 URL 和已有收藏兼容 |
| 3 | 实现 Ant Design 首页、榜单、卡片、详情、收藏与对比 | 核对全部既有功能；不同时运行旧 DOM 应用；空数据和缺少历史可正常显示 |
| 4 | 桌面与手机浏览器检查 | 320 / 390 / 768 / 1440 像素下无页面横向溢出；表格自身可横向滚动；键盘操作、明暗主题、中英文正常 |
| 5 | 更新 CI、Pages 构建与开发说明 | Python 测试、前端测试、生产构建通过，公开数据与 SEO 入口正确 |
| 6 | 推送部署并线上复查 | GitHub CI 与部署成功；正式子路径和英文入口加载正常；任务、搜索、收藏、详情与对比可用 |

完整迁移通过生产构建、功能回归及线上验证后，才作为完成交付。迁移期间先保留当前在线版本，避免把未完成的 React 页面推到主分支。

## 实施者负责的细节

依赖的具体兼容版本、组件文件名、测试文件组织和少量间距由实施者确定。采用标准 Ant Design 控件外观并套用白紫主题，业务信息结构和功能范围按本设计执行。
